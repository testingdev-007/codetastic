The 25-minute slot

Four stations, roughly 6 minutes each, with a short buffer for moving between them. The Construct taster has a visible on-screen countdown set to 6 minutes — the other three don't enforce a timer, so you'll need to call time yourself.

Construct ~6m
Vault ~6m
Ledger ~6m
Front ~6m

Nobody needs to finish every challenge in every activity — the point is a real taste of each, not full completion. If someone's clearly engaged and close on the last challenge when time's up, let them finish; don't cut mid-flow over a minute or two.

The Construct

What it is: navigating a hidden rover across a grid by writing real JavaScript — moveForward(), turnLeft(), turnRight() — building from a single command up to a loop. Covers functions, sequencing, and loops.

#TaskAsks for
1Wake Upcall moveForward() once
2The Pathfour moveForward() calls in a row
3The Turnmove, turn, move again — combining direction changes
BonusThe Glitchfix a loop that runs one time too few (debugging, not new syntax)

Scaffolded help

Tier 1 — ask, don't tell

"How many cells away is the exit? What do you think that number needs to be in your code?"

Tier 2 — point at the tool

Point them at the in-app Hint button before adding anything yourself — it's calibrated to nudge, not solve.

Tier 3 — narrow it down

"You've got the right idea, but count your moveForward() calls again — you're one short." Still make them fix it themselves.

The Vault

What it is: writing real functions to patch broken business logic in a bank's risk-checking system, then running real test cases against them. Covers functions, return values, booleans, and conditionals.

#FunctionAsks for
1calculateTotaladd a flat £5 fee to an amount
2isHighRiskreturn true/false for amounts over £10,000
3categoriseTransactionthree-way if/else banding
— take-home extension adds 3 more, see below —
4applyLoyaltyDiscounttwo parameters, one a boolean flag
5calculateInteresttwo-parameter arithmetic
6flagSuspiciousActivitycompound condition with &&

Scaffolded help

Tier 1 — ask, don't tell

"What does the Test Console say your function actually returned? Is that different from what it expected?"

Tier 2 — the usual suspects

Missing return, or > vs >= not matching the brief exactly — ask them to re-read the brief's wording once more before anything else.

Tier 3 — narrow it down

Point at the specific failing test row and the exact value it returned vs expected — that's usually enough for someone to spot it themselves.

function categoriseTransaction(amount) {
  if (amount > 10000) return 'flagged';
  if (amount >= 1000) return 'review';
  return 'standard';
}

function applyLoyaltyDiscount(amount, isPremium) {
  return isPremium ? amount * 0.9 : amount;

function calculateInterest(balance, rate) {
  return balance * (rate / 100);
}

}

The Ledger

What it is: writing functions that loop through a real (visible) list of transactions to answer questions — totals, filters, counts. Each function also gets tested against a second, hidden dataset, so hardcoding the visible numbers doesn't pass. Covers variables, arrays, objects, and loops.

#FunctionAsks for
1totalSpendaccumulator pattern — sum every amount
2sumByCategoryfiltered sum, one category
3countHighValuefiltered count against a threshold
— take-home extension adds 3 more, see below —
4largestTransactionrunning maximum
5averageTransactiondivision + rounding
6sumByCategoriesfilter against an array of categories

Scaffolded help

Tier 1 — ask, don't tell

"Where's your total variable declared — inside the loop, or before it?" This catches the single most common bug here on its own.

Tier 2 — read it aloud

Get them to read their if condition out loud in plain English — mismatches between what they meant and what they typed usually surface immediately.

Tier 3 — narrow it down

If the visible-ledger test passes but the hidden one fails, that's a strong sign they hardcoded a number instead of writing real logic — worth saying so directly.

Answer key

totalSpend
function totalSpend(transactions) {
  let total = 0;
  for (let i = 0; i < transactions.length; i++) {
    total += transactions[i].amount;
  }
  return total;
}
sumByCategory
function sumByCategory(transactions, category) {
  let total = 0;
  for (let i = 0; i < transactions.length; i++) {
    if (transactions[i].category === category) {
      total += transactions[i].amount;
    }
  }
  return total;
}
countHighValue
function countHighValue(transactions, threshold) {
  let count = 0;
  for (let i = 0; i < transactions.length; i++) {
    if (transactions[i].amount > threshold) {
      count++;
    }
  }
  return count;
}
largestTransaction (extension)
function largestTransaction(transactions) {
  let biggest = 0;
  for (let i = 0; i < transactions.length; i++) {
    if (transactions[i].amount > biggest) {
      biggest = transactions[i].amount;
    }
  }
  return biggest;
}
averageTransaction (extension)
function averageTransaction(transactions) {
  let total = 0;
  for (let i = 0; i < transactions.length; i++) {
    total += transactions[i].amount;
  }
  return Math.round(total / transactions.length);
}
sumByCategories (extension)
function sumByCategories(transactions, categories) {
  let total = 0;
  for (let i = 0; i < transactions.length; i++) {
    if (categories.includes(transactions[i].category)) {
      total += transactions[i].amount;
    }
  }
  return total;
}

The Front

What it is: writing real CSS against a live preview to hit stated visual goals — checked by reading actual computed styles, not exact pixel matching, so any reasonable colour/sizing choice passes. Covers selectors, the box model, typography, and flexbox.

#ScreenAsks for
1The Panelbackground, rounded corners, padding
2The Numbersfont-size, font-weight
3The Layoutflexbox row, space-between, centred

The take-home extension restructures this as one continuous page (header, nav, card, transaction list) instead of resetting between screens — same underlying skills, four sections instead of three, nothing wipes as you move between them.

Scaffolded help

Tier 1 — ask, don't tell

"What does the preview actually look like right now versus what you're going for?" Get them looking at the live preview, not just the code.

Tier 2 — the usual suspects

A missing semicolon silently breaks everything after it in that block — if nothing they add seems to work, check for one missing semicolon above it.

Tier 3 — narrow it down

display: flex has to go on the parent (the container), not the item inside it — this is the single most common flexbox mistake in the room.

Troubleshooting — user error, not the build

Every one of these has come up in testing and is a person doing something reasonable, not a bug in the files.

"I clicked Run and nothing happened."Check the Error box beneath the buttons — a syntax error (missing bracket, missing semicolon) stops the code from running at all, and the message is usually specific enough to spot the line. If the Error box is empty too, check they actually edited the function body — an empty // TODO with nothing added runs fine and just does nothing.
"My answer looks right but it's still failing."Almost always exact wording/case: "Groceries" won't match "groceries", and a typo'd function name (calculateTotall) means the test can't find the function at all — the error message will say so directly.
"The page looks completely unstyled / broken, no colours, no layout."The file was opened on its own outside the folder it came with (e.g. dragged out, or emailed as a single attachment). These are self-contained single files with no other dependencies, so this is almost always a font failing to load over a blocked network rather than a missing file — check internet access on that machine; the Google Fonts import is the only external request any of these make.
"I can't type in the code box."Click directly inside the text area first — cursor focus can land on a button instead, especially on a trackpad. Not a bug, just needs a click.
"I hit Reset and lost my code."Working as intended — Reset wipes back to the starter code for that challenge, not just the visuals. Worth warning the room about this once up front rather than after someone loses 4 minutes of work.
"The Vault/Ledger test console shows a weird value like NaN or undefined."NaN usually means a maths operation happened on something that wasn't a number (often a typo'd property name, e.g. transactions[i].amout). undefined almost always means a missing return — the function ran, but never sent anything back.
"Nothing in The Front changes when I edit the CSS."Check the selector actually matches — .account-card needs the dot; account-card without it targets a tag that doesn't exist and silently does nothing.
Construct taster vs. full build: the taster is genuinely a different file (mission-control-taster.html) with only 3 of 5 constructs and a 6-minute timer. Don't hand out the full mission-control.html link during the live event by mistake — its timer now counts up with no deadline, which will look odd if someone's expecting a countdown.

Chat help

Each of the four live tasters has a small green chat button in the bottom-right corner ("System Assist"). Participants can type a real question in their own words and get an instant hint — the point is to take pressure off you in the room, not to replace you.

How it actually works: there's no live AI model behind it — these are static files with no server. Each module ships with its own local knowledge base (16 entries for Construct, 15 for Vault, 15 for Ledger, 16 for Front) covering general concepts, per-challenge nudges, and common error messages. When someone types a question, it strips filler words ("what", "does", "how", "help", "meaning" — that kind of thing) and matches what's left against each entry's keyword list, then returns the best match. If nothing scores well enough, it says so honestly and points them at the in-app Hint button or a facilitator — it never invents an answer.

Where the content lives: the actual knowledge base is baked directly into each HTML file (not loaded from a separate file at runtime) — a JSON file opened directly by double-clicking, rather than served from a website, can silently fail to load its sibling files in some browsers, so the working copy is embedded for reliability. The matching construct-help.json / vault-help.json / ledger-help.json / front-help.json files are shipped alongside as the editable source — if you want to add or tweak an entry, edit the JSON file, then it needs re-embedding into the HTML before it'll actually take effect.

What it's good at: syntax questions, explaining an error message, nudging on a specific named challenge, and honestly saying "I don't know" for anything off-topic. What it won't do: write code for someone, or get pulled into small talk — it stays scoped to the activity on purpose.
