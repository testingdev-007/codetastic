Writing a function

A function takes some input (its parameters), does something with it, and sends a result back with return.

function double(n) {
  return n * 2;
}

double(5) runs the function with n set to 5, and gives you back 10. Nothing happens until it's actually called.

Common mistake: writing the logic but forgetting return — the function runs, but silently gives back undefined instead of your answer.

Booleans and comparison

A boolean is just true or false. Comparison operators produce one:

OperatorMeaning
>strictly greater than
>=greater than or equal to
< / <=less than / or equal to
===equal to (use this, not ==)
&&AND — both sides must be true
function isAdult(age) {
  return age >= 18;
}
Common mistake: mixing up > and >=. "Over 18" excludes exactly 18; "18 or over" includes it. Read the brief carefully — it's usually specific on purpose.

If / else

Run different code depending on a condition. The first matching branch wins — later ones are skipped.

function describe(n) {
  if (n > 100) {
    return "big";
  } else if (n > 10) {
    return "medium";
  } else {
    return "small";
  }
}

Order matters

Checks run top to bottom. Put the most specific or most extreme condition first — if you check the broadest one first, the narrower ones never get a chance to run.

What "testing" means here

Each test case calls your function with specific input and compares what it actually returns against what it's expected to return. A test only passes when those match exactly — a function that works for one input but not another still fails overall.
